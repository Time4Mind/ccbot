# ccbot

[![test](https://github.com/Time4Mind/ccbot/actions/workflows/test.yml/badge.svg)](https://github.com/Time4Mind/ccbot/actions/workflows/test.yml)
[![secrets-scan](https://github.com/Time4Mind/ccbot/actions/workflows/secrets-scan.yml/badge.svg)](https://github.com/Time4Mind/ccbot/actions/workflows/secrets-scan.yml)

[English README](README.md) · [中文文档](README_CN.md)

Личный Telegram-бот, соединяющий приватный 1-1 DM с N параллельными сессиями
Claude Code или Codex CLI в tmux. Один пользователь, N сессий, инлайн-переключатель в
самом свежем сообщении бота.

## Зачем

Claude Code живёт в терминале. Отошёл от стола — потерял видимость, но
сессия продолжает работать. ccbot позволяет:

- **Переключаться с десктопа на телефон в середине работы.** Claude
  делает рефакторинг — идёшь на прогулку и продолжаешь следить и
  отвечать из Telegram.
- **Возвращаться на десктоп в любой момент.** Сессии живут в реальных
  tmux-окнах, `tmux attach` возвращает в терминал с полной историей.
- **Параллельно вести несколько сессий.** У каждой — своё tmux-окно
  и свой процесс `claude`. Переключение активной сессии в Telegram не
  ставит остальные на паузу.

Бот — тонкий слой управления над tmux: процесс Claude Code остаётся
ровно там, где был. ccbot читает его вывод и отправляет нажатия
клавиш.

## Отличия от upstream

Этот форк сознательно расходится с upstream `ccbot` в нескольких
принципиальных моментах:

- **Только DM.** Никаких супергрупп, форум-топиков, thread-routing'а.
  Бот видит исключительно приватный 1-1 чат с allowlisted
  Telegram-юзером.
- **Личный бот с allowlist'ом.** Обычно в `ALLOWED_USERS` один
  числовой Telegram-id. Несколько id поддерживаются как *общий
  workspace*: пул сессий глобальный, каждое событие claude веерно
  уходит в личку каждому разрешённому юзеру (своя карточка, свой
  переключатель). Это не multi-tenant — все видят всё. Сообщение от
  не-allowlisted отправителя молча отбрасывается (без ответа, без
  callback-тоста) — для постороннего бот выглядит мёртвым.
- **Только bypass-режим.** Claude запускается с
  `--dangerously-skip-permissions`, Codex — с
  `--dangerously-bypass-approvals-and-sandbox`. Релэя permission-промптов в
  Telegram нет — если не доверяешь модели полный доступ к хосту,
  используй upstream. (Остаточные Yes/No-промпты, которые bypass не
  снимает — например доверие домену в WebFetch — приходят
  клавиатурой либо автоотвечаются через `Настройки → Авто-
  подтверждение`.)
- **Multi-session с инлайн-переключателем.** В одном DM может жить
  много сессий; инлайн-клавиатура под последним сообщением бота
  переключает между ними.
- **Rich-сообщения в первую очередь.** Вывод уходит как rich-message
  Bot API 10.3 (нативный markdown: GFM-таблицы ≤ 20 колонок,
  заголовки, `<details>`, сноски, формулы), с фолбэком на MarkdownV2
  (`telegramify-markdown`) и дальше на plain text при любой ошибке.
  Fenced shell-команды (включая PowerShell и cmd) превращаются в
  копируемый code-текст, чтобы Telegram показывал для них Copy; блоки
  исходного кода сохраняют подсветку и компоновку. Полные локальные пути
  в ответах превращаются в имя файла и кнопку-ссылку только с его расширением;
  поддерживаются абсолютные пути и `~/...`.
  Kill switch: `CCBOT_RICH_MESSAGES=off`. В upstream — HTML.
- **Hook-based session tracking.** Хуки выбранного агента `SessionStart` +
  `UserPromptSubmit` пишут `session_map.json`; монитор бота его
  опрашивает. Никаких process-tree introspection или claude SDK.
- **Голос - local-first.** Parakeet через NeMo-Speech.cpp (по умолчанию,
  как в Bria), legacy `whisper.cpp` или Apple Speech через PyObjC на
  macOS - API-ключ для запуска не нужен.

Историческая архитектурная мотивация - в `doc/dm-multisession-spec.md`,
а завершённый план исходного рефакторинга - в `doc/dm-multisession-plan.md`.
Текущее пользовательское поведение описано в этом README.

## Требования

- **tmux** в `PATH`
- **Claude Code** CLI (`claude`) или **Codex CLI** (`codex`); Codex может
  авторизоваться через Telegram при первом запуске
- **Python 3.12+**
- **uv** (рекомендуется) для управления зависимостями
- macOS (Apple Silicon) или Linux x86_64/arm64

Опционально:

- **`ffmpeg`** + **`whisper-cli`** для локальной голосовой транскрипции
- **`ffmpeg`** + **`nemo-speech`** + Parakeet q8-модель для режима
  `VOICE_BACKEND=auto|parakeet`
- **`pyobjc-framework-Speech`** для нативного Apple Speech-бэкенда
  (`uv sync --extra apple-speech`)

## Быстрый старт

```bash
git clone https://github.com/Time4Mind/ccbot.git
cd ccbot
uv sync
cp .env.example ~/.ccbot/.env   # вписать TELEGRAM_BOT_TOKEN + ALLOWED_USERS
ccbot hook --install            # Claude; для Codex добавь --backend codex
ccbot                           # foreground; для prod — systemd-юнит
```

Полная пошаговая установка на Linux (написана так, чтобы её мог
выполнить AI-агент) — в `doc/install-linux.md`.

## Конфигурация

Обязательные env-переменные в `~/.ccbot/.env` (или `./.env`):

| Переменная           | Описание                                        |
| -------------------- | ----------------------------------------------- |
| `TELEGRAM_BOT_TOKEN` | Токен от [@BotFather](https://t.me/BotFather)   |
| `ALLOWED_USERS`      | Один числовой Telegram-user-id                  |

Чаще всего настраиваемые опциональные:

| Переменная                  | По умолчанию | Эффект |
| --------------------------- | ------------ | ------ |
| `CCBOT_DIR`                 | `~/.ccbot`   | Каталог конфигов и состояния |
| `TMUX_SESSION_NAME`         | `ccbot`      | tmux-сессия, где живут все session-окна |
| `CCBOT_AGENT_BACKEND`       | `claude`     | Начальный глобальный backend для нового state |
| `CLAUDE_COMMAND`            | `claude`     | бинарь для старта сессии |
| `CLAUDE_FLAGS`              | `--dangerously-skip-permissions` | флаги для `claude` |
| `CODEX_COMMAND`             | `codex`      | бинарь Codex CLI (можно указать абсолютный Termux-путь) |
| `CODEX_FLAGS`               | bypass + hook trust + hooks + `--no-alt-screen` | флаги для `codex` |
| `CODEX_NAMING_MODEL`        | `gpt-5.6-luna` | легковесная модель Codex для автоматических имён сессий |
| `ARCHIVE_PURGE_AFTER`       | `20d`        | архивные сессии удаляются из state через столько; transcript остаётся на диске |
| `QUOTA_ALERT_POLL_INTERVAL` | `10m`        | как часто опрашивается живой `/usage` |
| `VOICE_BACKEND`             | `auto`       | `auto` / `parakeet` / `whisper` / `apple` / `off`; `auto` выбирает Parakeet |
| `PARAKEET_BIN`              | `nemo-speech` | бинарь NeMo-Speech.cpp |
| `PARAKEET_MODEL_PATH`       | `~/.ccbot/models/parakeet-tdt-0.6b-v3.q8_0.gguf` | локальная Parakeet-модель, совместимая с Bria |
| `WHISPER_MODEL_PATH`        | `~/.ccbot/models/ggml-medium-q8_0.bin` | модель whisper.cpp (фолбэк на уже стоящий `ggml-medium.bin`) |
| `WHISPER_LANG_MODEL_PATH`   | `~/.ccbot/models/ggml-tiny.bin` | tiny-модель для пре-пасса определения языка |
| `WHISPER_LANG_DEFAULT`      | `ru`         | язык по умолчанию, когда детект не уверен |
| `WHISPER_THREADS`           | `6`          | потоки для `whisper-cli` (его собственный дефолт — 4) |
| `BG_STATUS_MAX`             | `4`          | макс. бейджей в bg-status-панели; остальные сворачиваются в `+N more` |
| `CARD_EDIT_LAG`             | `2.0`        | окно коалесцинга редактирований карточки (секунды) |
| `CCBOT_RICH_MESSAGES`       | `on`         | `off` выключает rich-сообщения Bot API 10.3 (останется MarkdownV2) |
| `CCBOT_HOST`                | hostname     | метка деплоя, экспортируется в сессии как `CCBOT_HOST` |
| `TG_PROXY_URL`              | _(не задан)_ | outbound-прокси для Bot API (`socks5://…` или `http://…`) |

Актуальный список env-переменных - в `.env.example`; product spec хранит
историческую мотивацию и может отставать от текущего интерфейса.
Персональные UI-настройки (размер карточки, уведомления, голосовой
бэкенд, язык…) живут за `≡ Меню → Настройки`. В разделе
`Сессии и бэкенды` можно независимо включить Claude и Codex; последний
активный backend выключить нельзя. Если включены оба, при создании сессии
сначала выбирается backend, затем директория. `CCBOT_AGENT_BACKEND` задаёт
только первоначальный выбор для нового state.
Если включить отсутствующий backend из Telegram-настроек, ccbot предложит
установить официальный npm-пакет Claude/Codex, затем запустит его штатный
flow авторизации. Для этого на хосте должны быть доступны Node.js и `npm`.

## Установка хука

Бот трекает связки tmux-окно → agent-session через два lifecycle-хука:
`SessionStart` ловит каждый новый процесс агента, а
`UserPromptSubmit` на каждом промпте чинит устаревший маппинг
(покрывает `/resume`, `/clear` и гонки при рестарте бота). Авто-
установка одной командой:

```bash
ccbot hook --install
```

Для Codex backend:

```bash
ccbot hook --install --backend codex
```

Codex использует те же lifecycle-события `SessionStart` и
`UserPromptSubmit`; ccbot устанавливает их в `~/.codex/hooks.json`. Чтобы
параллельно создавать сессии обоих типов, установи hooks обоих backend и
включи их в `Настройки → Сессии и бэкенды → Агент`. Уже созданная сессия
всегда сохраняет свой backend. Restore запускает нативный backend архива,
если он включён; иначе выполняется cross-agent pickup через ограниченный
handoff. Исходный transcript не изменяется.

Пошаговая установка в Termux — [doc/install-termux.md](doc/install-termux.md).

Установщик идемпотентен по событиям — повторный запуск на старой
`SessionStart`-only инсталляции просто дописывает недостающую запись.

Или вручную в `~/.claude/settings.json`:

```json
{
  "hooks": {
    "SessionStart": [
      { "hooks": [{ "type": "command", "command": "ccbot hook", "timeout": 5 }] }
    ],
    "UserPromptSubmit": [
      { "hooks": [{ "type": "command", "command": "ccbot hook", "timeout": 5 }] }
    ]
  }
}
```

## Использование

Бот публикует небольшое slash-меню в `/`-меню Telegram плюс инлайн-
кнопку `≡ Меню` под самым свежим сообщением:

| Команда    | Эффект |
| ---------- | ------ |
| `/menu`    | Открыть инлайн ≡ Меню |
| `/help`    | Краткий гайд (раздельные секции с инлайн-навигацией) |
| `/model`   | Открыть выбор модели активного бэкенда |

Ещё несколько команд работают при наборе, но в `/`-меню не показаны:
`/new`, `/kill`, `/stop`, `/archive`, `/usage`, `/clear`, `/cost`,
`/health`, `/login`.

**`/login` — переавторизация Claude с телефона.** Когда OAuth-логин под
`claude` истекает, все сессии начинают падать, и починить это без
десктопа обычно нельзя. Самому боту авторизация Claude не нужна —
поэтому он замечает падение, присылает 🔐-уведомление, а `/login`
проводит обмен: бот даёт ссылку, ты подтверждаешь в браузере телефона
(редирект идёт на `platform.claude.com`, а не на localhost, так что
туннель не нужен) и присылаешь показанный на странице код обычным
сообщением. Бот скармливает его ждущему процессу, подтверждает новый
срок и удаляет твоё сообщение с кодом. После этого он заново присылает
карточку активной сессии (или Меню, если активной нет), чтобы ты
продолжил с того же места, а не листал историю выше обмена.

Для backend Codex авторизация запускается автоматически при первом старте
бота. Бот проверяет `account/read` через Codex app-server; если аккаунта нет,
присылает в Telegram официальную ссылку и device code, ждёт
`account/login/completed` и только после этого разрешает создавать сессии.
Код вводится на странице OpenAI и обратно в чат не отправляется. `/login`
вручную перезапускает тот же flow.

Уведомление срабатывает по собственной error-записи Claude Code
(`isApiErrorMessage` / `authentication_failed`), а не по тексту ошибки —
сессия, которая просто пишет про мёртвый логин, его не поднимет. Свежий
логин отодвигает дедлайн креденшлов примерно на 30 дней; именно этот
дедлайн и важен, потому что ротация refresh-токена его не двигает.

В инлайн-меню остаются четыре действия: `Sessions`, `Archive`, `New`,
`Settings`. Над ними встроена таблица лимитов. Каждый тап Меню сразу
рисует кэш, показывает `⏳` рядом с его возрастом и обновляет лимиты в фоне.
Кнопка *Опции* в активной карточке раскрывает
настроенные действия над переключателем сессий. Скрин включает
изображения глобально, а Терминал открывает только текущую сессию.
Кнопка Терминала по умолчанию скрыта.

### Сессии и переключатель

Отправь любой текст в DM, чтобы создать первую сессию. Если резервная
сессия выключена, бот откроет браузер директорий; при двух включённых
backend перед ним появится выбор Claude/Codex. После выбора проекта агент
стартует в tmux, а запрос остаётся в очереди до готовности его ввода.
Дальнейший текст в DM роутится в **активную** сессию.

Опциональная *резервная сессия* настраивается в
`Настройки → Сессии и бэкенды`: выбираются директория и backend, после чего
ccbot постоянно держит ровно одну пустую предзапущенную сессию `default`.
Первый запрос атомарно превращает её в обычную сессию с именем
`<директория>-N` и сразу запускает новый пустой резерв. Пустой резерв виден в
переключателе как `⚪ default`, не архивируется по idle-TTL и удаляется при
выключении настройки, только пока он действительно пуст.

Меню, Новая, Архив и Настройки временно получают исключительное владение
текущим carrier-сообщением. Выбранная сессия продолжает работать в фоне, но
не может перерисовать поверх открытого экрана свою карточку. Назад из flow
создания возвращает прямо в прежнюю активную карточку; выбор директории
превращает тот же carrier в карточку новой сессии, не создавая промежуточного
сообщения.

Список папок сразу рисуется из кэша или быстрой меты файловой системы и Git.
Один фоновый проход вычисляет свежесть вложенного содержимого сразу для всех
посещённых директорий; деревья зависимостей и кэшей игнорируются.

Имя сессии сначала берётся из имени каталога, а на первом сообщении
длиной ≥ 20 символов один раз переписывается коротким отдельным
запросом: Haiku для Claude или `CODEX_NAMING_MODEL` для Codex (по
умолчанию `gpt-5.6-luna`). Результат — два слова о сути, например
`token budget`. Автоименование выключается в настройках; тогда остаётся
имя каталога и отдельный модельный вызов не выполняется.

В самом свежем сообщении бота — инлайн-переключатель
(`▷ session-A · session-B`), а внизу — парный ряд `[+ new] [≡ Меню]`:
две кнопки «уйти отсюда» рядом друг с другом, слот стабилен между
видами (в *Меню → Sessions* / *Archive* этот же слот занимает
`[+ new] [Back]`).

Кнопки переключателя идут **от старых к новым**: сессия сохраняет свой
слот на всю жизнь, а только что созданная добавляется справа — мышечная
память не ломается при переключении. Восстановленная из архива сессия
возвращается самой новой кнопкой, а не в свой исходный слот.

Тап на любую сессию **рисует её живую карточку** с последними ходами и
пагинацией прямо на carrier-сообщении и одновременно делает сессию активной.
Предыдущие страницы загруженной истории открываются кнопками пагинации
на самой карточке.

Reply-цитата на сообщение бота из неактивной сессии роутит твой
текст туда разово, без смены активной.

*Меню → Archive* показывает пронумерованный список прошлых сессий
по две кнопки в ряд. У каждой строки - описание суммарно до 70 символов:
по умолчанию это два самых ранних доступных текстовых запроса пользователя,
каждый с префиксом `·`. Внешний harness-контекст, системные инструкции и
сырой HTML файлов исключаются; если текстовых запросов нет, остаются короткие
медиа-теги вроде `#image`. Опциональное `AI-описание` сжимает те же исходные
запросы легковесной моделью. Пустые сессии в архив не попадают и очищаются
из старого state. Тап по сессии рисует реальный transcript прямо с диска
(JSONL), начиная с последней страницы карточки; старую часть длинной истории
можно открыть после восстановления сессии. *Restore* / *Delete* остаются в
футере.

### Фоновые сессии

У фоновых (неактивных) сессий **нет собственной живой карточки** —
они не редактируют карточку и не выводят AskUserQuestion-промпт в чат.
Их состояние проявляется компактной панелью внизу карточки активной
сессии:

```
🟦 session-A ⏳        ← работает в фоне
🟪 scraper   ✅        ← завершилась
🟧 chores    ❌        ← упала
🟨 frontend  ❓        ← требует действия (AskUserQuestion / permission)
```

Панель «липкая» поверх редактирований активной карточки, чтобы
завершившаяся фоновая сессия не потерялась над длинным tool-логом.
Тап по бейджу (через переключатель) убирает его из панели — ты
«увидел». Если бейдж `❓`, тап рисует сохранённый AskUserQuestion /
ExitPlanMode-промпт с теми же стрелками/Enter/Esc, что и на
foreground-промпте.

Поверх бейджа фоновая сессия может прислать короткий пуш
(`✅ [scraper] task complete`) — только на *смене состояния*. Три
независимых тумблера в *Настройках → 🔔 Уведомления*, все включены по
умолчанию: `Bg: задача готова`, `Bg: ошибки`, `Bg: нужно действие`.
Выключи их, чтобы фон работал совсем молча.

### Живая карточка

У каждой активной сессии — одно сообщение-карточка, которое бот
редактирует: шапка, тело с пагинацией, bg-панель, футер-клавиатура.
Каждое твоё сообщение репостит карточку под твой текст (поведение
теперь одно; настройка `Card position` убрана). Над bg-панелью
печатается `context: N%` сессии: для Codex это точные данные `token_count`
из rollout, для Claude — аппроксимация claude'овского
`/context`, посчитанная по JSONL, обычно в пределах ±10 % от модалки.

Финальный ответ активной сессии публикуется новой карточкой. Старый carrier
остаётся на открытой пользователем странице, но лишается клавиатуры; новая
карточка при создании получает `✅` перед значком сессии, а первое последующее
обновление снимает галочку. Это сохраняет порядок turn'ов и не возвращает
пользователя с выбранной страницы к актуальной.

Tool-вызовы показываются раскрываемыми блоками: команда и результат разделены
строкой `- - -`. JSON, табличный вывод и пары `key=value` по возможности
приводятся к читаемой структуре `ключ: значение`; буквальные `\n` и лишнее
экранирование очищаются. Ограничения применяются после структурирования,
отдельно к команде и результату: `5 / 10 / 30 / 60` строк, по 100 символов
на строку. Полные пути к существующим файлам становятся кнопками скачивания.

Настройки карточки — в *Настройках → 🃏 Карточка / вид*:

| Настройка | Дефолт | Эффект |
| --------- | ------ | ------ |
| `История в карточке` | `20` | сколько end-of-turn-границ подгружается в свежую карточку из JSONL (переживает рестарт бота) |
| `Размер страницы` | `20` строк | максимум строк на страницу; длинное тело режется по границам абзацев/предложений |
| `Строк команды` | `10` | лимит строк команды внутри tool-спойлера после структурирования |
| `Строк результата` | `10` | независимый лимит результата внутри tool-спойлера |
| `Объём скрина` | `48 KiB` | максимум свежего текста терминала для изображения |
| `Качество скрина` | `100%, оптимизировано` | масштаб и цветовой профиль |
| `Лаг карточки` | `4s` | окно коалесцинга обновлений превью |

Видимость кнопок Скрин и Терминал задаётся в *Настройки → Кнопки
опций*. Скрин по умолчанию виден, Терминал - нет. Нажатие Скрина меняет
глобальное состояние в той же карточке. Последний pane сохраняется в **IDLE**.
Порядок блоков: `тело → отступ → pane → отступ → context → фоновые сессии`.
Rich Bot API держит текст и картинку в одной карточке; при недоступности rich
media остаётся та же text-only карточка, а следующее обычное обновление повторит скрин.
Если незавершённый turn подозрительно замолчал, активная карточка сохраняет
pane без заглушки и отдельного push. У фоновой сессии в этом случае появляется
только `⚠️` напротив её имени в блоке фоновых сессий.

Индикатор Telegram **`печатает…`** в шапке чата управляется
реальными событиями claude. Пока активная сессия эмитит (tool-call,
thinking, текст) — `печатает…` горит; idle-сессия даёт ему погаснуть
в течение ~5 с (Telegram-окно).

### Прочие настройки

*≡ Меню → Настройки* включают Сессии и бэкенды, 🃏 Карточку / вид,
🔔 Уведомления, 🎙 Голос, 🖥 Локальный терминал, ⋯ Кнопки опций,
💻 Препроцессинг и ⚙ Поведение и язык.
Что стоит знать:

- **Авто-подтверждение** (по умолчанию `off`) — автоответ на те
  интерактивные Yes/No-промпты, которые `--dangerously-skip-permissions`
  не снимает (доверие домену в WebFetch и т. п.). Если авто-Yes не
  убрал промпт, бот эскалирует на ручную клавиатуру, а не зацикливается.
  Входящий запрос в этот момент не теряется: закреплённая за сессией FIFO
  ждёт исчезновения prompt и только затем продолжает доставку.
- **Препроцессинг** (по умолчанию `Выключен`) — одна скрытая постоянная
  сессия Codex на `gpt-5.6-luna` консервативно редактирует запрос перед
  отправкой. Режимы: `Только голос` и `Все запросы`; инструкцию можно заменить.
  Satellite запускается при включении настройки или при старте ccbot, если
  режим уже активен. Лимит одного прохода - 15 секунд; при ошибке исходный
  запрос всё равно уходит в закреплённую сессию.
- **Локальный терминал** - здесь выбирается Linux-эмулятор, если он
  нужен. Видимость кнопки задаётся отдельно в *Кнопках опций*;
  автоматического открытия новых терминалов нет.
- **Сброс недели** — нужен только Claude, чей `/usage` сообщает время,
  но не полный timestamp. Codex отдаёт точное время сброса через
  app-server, поэтому отдельная настройка дня ему не нужна.
- **Язык** — `en` / `ru` / `zh` для UI-строк самого бота.

### Лимиты в Меню

Встроенная в *≡ Меню* таблица использует источник выбранного backend.
Отдельных кнопок Статус и Обновить нет:

- Claude: живая `/usage`-модалка через выделенное tmux-окно
  `ccbot-usage`;
- Codex: `account/rateLimits/read` поддерживаемого app-server API, без
  ввода команд в рабочую сессию.

Claude отображается в прежнем компактном виде:

```
Claude Code
🟡 5h: 62% · 12.4%/h · 17:00
🟢 week: 28% · 4.0%/d · Mon 17:00
🟢 week (Sonnet): 12% · Mon 17:00
```

Для Codex недельный блок показывает практически полезный дневной бюджет:

```
OpenAI Codex

🟢 5ч

Использовано: 12%

Сброс: 14:30

🟢 неделя

Использовано: 50%

Сегодня: ещё 10.0%

Сброс: 05.08 17:00
```

В начале календарного дня остаток недельной квоты делится поровну между
сегодняшним днём и всеми оставшимися датами до дня сброса включительно.
Внутри дня бюджет фиксирован, а строка `Сегодня` уменьшается на
фактический расход. При превышении она показывает `перерасход N%`. На
следующей календарной дате реальный остаток распределяется заново,
поэтому перерасход и недорасход автоматически меняют бюджеты следующих
дней. Дневная точка создаётся только по свежему успешному чтению usage,
хранится в `$CCBOT_DIR/codex_quota_day.json` и переживает рестарт. Отрисовка
меню из кэша не создаёт и не пересчитывает точку. Выбранный backend
опрашивается в фоне с интервалом `QUOTA_ALERT_POLL_INTERVAL` (по умолчанию
10 минут).

Для Claude этот же фоновый опрос шлёт алерт при пересечении 50 / 75 / 90 %
по 5-часовому или недельному окну. Публикуются только «устаканившиеся»
чтения — недорисованная модалка не выстрелит фантомным алертом.

### Голос и медиа

- **Голосовые сообщения** транскрибируются локально (Parakeet по умолчанию;
  whisper.cpp / Apple Speech остаются явными вариантами) и попадают в
  активную сессию как набранный текст. На
  время транскрипции в карточке висит pending-маркер, затем он
  заменяется распознанным текстом — видно, что именно получил агент.
  Сообщение закрепляется за выбранной при приёме сессией. Длинный текст
  передаётся в tmux UTF-8-безопасными чанками, а последующие запросы этой
  сессии сохраняют FIFO-порядок. Если после распознавания в терминале открыт
  approval/AskUserQuestion, запрос остаётся в очереди до освобождения pane,
  а не исчезает и не попадает в интерактивный prompt.
  Legacy Whisper-путь на эталонном arm64-хосте занимает ~9 с: квантованная
  `ggml-medium-q8_0` (в 1.8× быстрее fp16, транскрипты на ru/en-
  сэмплах идентичны) плюс пре-пасс определения языка на `ggml-tiny`,
  благодаря которому основной проход пиннит `-l` и кодирует один раз.
  Для явного Whisper-варианта *Настройки → 🎙 Голос* предлагают установку
  whisper.cpp и обеих моделей.
- **Фото и документы** ложатся в `<workdir>/.ccbot-inbox/`, агент получает
  относительный путь и пользовательскую подпись через tmux. Файлы
  авто-чистятся через 24 часа. Если включён препроцессинг всех запросов,
  редактируется только подпись; байты файла не меняются.
- **Пересланные Rich Markdown-сообщения с картинками** сохраняют текст и
  каждую вложенную картинку в одном запросе к целевой сессии. Из набора
  Telegram `PhotoSize` выбирается самый большой доступный вариант.
  У прочих пересланных медиа (video / GIF / sticker) сохраняются caption и
  скрытые `text_link`-URL, но сам неподдерживаемый payload отбрасывается.
- **Граница препроцессинга по автору:** прямой текст/голос/подпись Артёма и
  пересланное им собственное сообщение обрабатываются; пересылки другого
  пользователя, канала, бота, самого ccbot и сообщения через `via_bot` идут
  без изменения. Новый текст Артёма в reply обрабатывается, процитированная
  часть остаётся как есть. Вставленный вручную чужой текст технически
  неотличим от прямого и считается пользовательским вводом.

├── session_monitor.py      — JSONL polling, NewMessage callbacks
├── codex_session_io.py     — поиск и чтение Codex rollout JSONL

├── codex_usage.py          — rate limits через Codex app-server
├── session_import.py       — cross-agent handoff при restore

├── inbound_queue.py        — закреплённая per-session FIFO входящих запросов
├── request_preprocessing.py — скрытая Luna-сессия препроцессинга

├── voice_install.py        — авто-установщик whisper.cpp + моделей
├── local_terminal.py       — аттач нативного терминала

│   ├── app.py              — bootstrap, post_init / post_shutdown
│   ├── messages.py         — text / voice / photo / document / forward

│   ├── commands/           — тела slash-команд

└── handlers/
    ├── notifications.py    — live cards + push events
    ├── card_model.py       — модель карточки: state / render / пагинация
    ├── bg_status.py        — панель статусов фоновых сессий
    ├── archive.py          — /archive рендер + idle sweeps
    ├── quota_alerts.py     — фоновый /usage poll

Состояние — в `$CCBOT_DIR` (по умолчанию `~/.ccbot/`):

| Файл                | Содержимое |
| ------------------- | ---------- |
| `state.json`        | сессии, active_sessions, window states, user settings |
| `session_map.json`  | hook-генерируемая tmux-window → agent-session карта |
| `monitor_state.json`| per-JSONL byte offsets (защита от дублей при рестарте) |
| `codex_quota_day.json` | дневная точка и бюджет Codex |
| `ccbot.lock`        | эксклюзивный flock живого бота; второй старт отваливается с кодом 1 |

## Надёжность

- **Один инстанс.** `main.py` держит эксклюзивный `flock` на
  `ccbot.lock` весь свой жизненный цикл — рестарт супервизора,
  наложившийся на ручной запуск, не породит двух ботов, дерущихся за
  `getUpdates`.
- **Watchdog long-poll'а.** Отдельный поток ловит молча зависший
  long-poll, а на затяжном сетевом обрыве процесс сам выходит, вместо
  того чтобы висеть немым — супервизор/systemd поднимут его, когда
  сеть вернётся.
- **Восстановление на старте.** Сессии с живым tmux-окном
  переподключаются, исчезнувшие помечаются `lost` (с кнопкой
  `Restore`), а tmux-окна без привязки логируются как orphan'ы, а не
  убиваются.
- **Закреплённая доставка.** Каждый входящий запрос синхронно получает
  целевое tmux-окно и место в FIFO этой сессии до первого `await`.
  Переключение карточки не перенаправляет уже принятый запрос, а открытый
  terminal prompt лишь приостанавливает очередь до освобождения pane.
- **Восстановление препроцессинга.** До отправки в tmux pending-запрос
  сохраняется в `state.json`; после рестарта ccbot сверяет transcript и
  либо подтверждает уже доставленный запрос, либо безопасно продолжает его.

## Развёртывание

systemd-юнит лежит в `scripts/ccbot.service`; на хостах с нестабильным
аплинком можно вместо него гонять `scripts/ccbot-supervisor.sh` — он
ждёт сеть перед каждым стартом и рестартует с backoff'ом. Для
VPS-хостов без прямого доступа к `api.telegram.org` — SSH-tunnel-рецепт
через `TG_PROXY_URL` в `doc/deploy.md`. Полная пошаговая Linux-
инсталляция (для AI-агента) — `doc/install-linux.md`.
